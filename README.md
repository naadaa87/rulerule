# 룰룰 | 보드게임 룰 하는법 설명서

보드게임과 전통놀이 하는 법을 1분 요약, 따라하기, 자세한 규칙 순서로 알려 주는 웹사이트예요. 게임 중에 휴대폰을 테이블에 두고 쓰는 테이블 모드와, 보드게임카페나 파티룸에서 쓰는 매장 QR 기능이 들어 있어요.

- 게임 80가지: 보드게임 64가지, 전통놀이 16가지
- 게임 찾기: 인원, 시간, 난이도, 종류, 분위기로 거르기와 초성 검색(예: ㅎㄹㄱㄹ)
- 게임 페이지: 1분 요약, 따라하기(구성물 확인, 준비, 예시), 자세한 규칙, 헷갈리는 상황, 우리 집 규칙 정하기
- 테이블 모드: 단계별 안내, 화면 켜 두기, 밤 화면, 글씨 크기, 점수판, 타이머, 주사위, 누가 먼저, 팀 나누기, 윷 던지기, 역할 나누기(마피아, 아발론), 제시어 나누기(라이어 게임)
- 매장 QR: 매장 이름과 게임을 고르면 매장 페이지, QR 이미지, 인쇄용 안내문과 게임별 QR 스티커가 만들어져요. 매장 정보는 주소 안에만 담기고 서버에 저장되지 않아요.
- 보드게임 룰 모음(/rules/): 80가지 게임의 하는법을 가나다순으로 모은 페이지
- 재미로 알아보기: 보드게임 이야기(/stories/, 게임마다 유래·역사·재미있는 사실과 퀴즈 3문제), 나에게 맞는 보드게임 테스트(/test/, 8가지 유형과 인원·시간에 맞는 추천), 보드게임 월드컵(/worldcup/, 모두의 순위), 상식 퀴즈(/quiz/)
- 룰룰 보드게임몰(/shop/)과 게임 페이지의 ‘구매하기’: 쿠팡 파트너스 링크로 연결하고, 몇 번 눌렸는지 세요
- 커뮤니티(/community/): 회원가입, 지역별 모임, 정모·번개 일정과 참여 신청, 게시판(자유, 규칙 질문, 게임 후기, 추천, 투표, 공지), 댓글, 좋아요, 신고
- 참여 기능: 게임마다 별점·후기(추천 인원, 체감 난이도, 도움돼요), 저장·해 봤어요·하고 싶어요, 투표, 규칙 질문 답변 채택, 정모 뒤 매너 별점
- 성장 기능: 활동 점수와 10단계 등급, 받은 별, 배지 20가지와 대표 배지, 출석 체크와 연속 출석, 알림, 보드게임 도감, 랭킹(/community/rank/), 공개 프로필, 등급 안내(/community/levels/)
- 저장한 게임(/saved/): 저장, 최근 본 게임(보던 단계부터 이어 보기), 해 본 게임, 하고 싶은 게임
- 제휴·문의(/contact/), 이용약관, 개인정보처리방침, 커뮤니티 이용 규칙
- 틀린 곳 알려 주기, 운영 관리 화면(대시보드, 지표 KPI, 원고 관리, 오류 신고, 문의함, 커뮤니티, 쇼핑 링크, 쿠팡 실적 입력, 설정)
- 한 번 본 페이지는 인터넷이 끊겨도 열려요(PWA).

원고 상태는 세 가지예요. **검수 중(draft)**, 참고 자료와 견줘 본 **자료 대조 완료(reviewed)**, 실제 게임으로 확인한 **검수 완료(checked)**. 지금은 17개가 자료 대조 완료이고 나머지는 검수 중이에요. 실제 게임으로 확인한 뒤 하나씩 검수 완료로 바꿔 주세요. 방법은 아래 ‘원고 고치기’에 있어요.

## 1. Cloudflare에 배포하기

모두 브라우저에서 할 수 있어요. 터미널은 필요 없어요.

### 1-1. Pages 프로젝트 만들기

1. [Cloudflare 대시보드](https://dash.cloudflare.com)에 들어가 왼쪽 메뉴에서 **Workers & Pages**를 눌러요.
2. **Create**(만들기)를 누르고 **Pages** 탭에서 **Connect to Git**(Git에 연결)을 골라요.
   Pages 탭이 보이지 않으면 화면 아래쪽 ‘Looking to deploy Pages?’ 링크를 누르세요.
3. GitHub 계정을 연결하고 이 저장소(`naadaa87/rulerule`)를 골라요.
4. 빌드 설정을 이렇게 넣어요.

   | 항목 | 값 |
   | --- | --- |
   | 프로젝트 이름 | `rulerule` (사이트 주소가 `rulerule.pages.dev`가 돼요) |
   | 프로덕션 브랜치 | `main` |
   | 프레임워크 프리셋 | None (없음) |
   | 빌드 명령 | `npm run build` |
   | 빌드 출력 디렉터리 | `public` |

5. **Save and Deploy**(저장 및 배포)를 누르면 1~2분 뒤 사이트가 열려요.

> 프로젝트 이름을 `rulerule`로 쓸 수 없어 다른 이름을 썼다면, 이 저장소의 `site.config.json`에서 `siteUrl`을 실제 주소로 바꿔 주세요. 검색 노출용 주소와 공유 이미지 주소가 여기서 정해져요.

### 1-2. 신고함과 이용 기록용 데이터베이스(D1) 연결하기

사이트는 이 단계 없이도 열려요. 틀린 곳 알려 주기, 이용 기록, 운영 관리 화면을 쓰려면 연결해 주세요.

1. 대시보드 왼쪽 메뉴에서 **Storage & Databases → D1 SQL Database**(또는 **Workers & Pages → D1**)로 가서 **Create**(만들기)를 눌러요. 이름은 `rulerule-db`로 해요.
2. **Workers & Pages → rulerule → Settings(설정) → Bindings(바인딩)**에서 **Add**(추가) → **D1 database**를 골라요.
   - Variable name(변수 이름): `DB` (대문자 그대로)
   - D1 database: `rulerule-db`
3. 같은 설정 화면의 **Variables and Secrets**(변수 및 비밀)에서 **Add**(추가)를 눌러요.
   - Type(유형): **Secret**(비밀)
   - Variable name: `ADMIN_PASSWORD`
   - Value: 운영 관리 화면에 쓸 비밀번호 (길고 남이 짐작하기 어렵게)
4. 설정은 다음 배포부터 적용돼요. **Deployments**(배포) 탭에서 가장 최근 배포 오른쪽 메뉴(…)를 눌러 **Retry deployment**(배포 다시 시도)를 해 주세요.
5. 확인: 브라우저에서 `https://rulerule.pages.dev/api/health`를 열어 `"db":true,"admin":true`가 보이면 끝이에요.

표(테이블)는 처음 쓸 때 저절로 만들어져요. SQL을 따로 실행하지 않아도 돼요.

### 1-3. 운영 관리 화면

`https://rulerule.kr/admin/`에서 위 비밀번호로 들어가요. 로그인은 12시간(‘7일 유지’를 고르면 7일) 이어지고, 비밀번호를 15분 안에 8번 틀리면 잠시 막혀요. 처음 로그인한 브라우저는 방문 통계에서 자동으로 빠져요(설정·도움말에서 바꿀 수 있어요).

왼쪽 메뉴(휴대폰은 위쪽 줄)로 화면을 옮기고, 주소 뒤의 `#/kpi/overview` 같은 이름으로 바로 열 수도 있어요.

| 메뉴 | 하는 일 |
| --- | --- |
| 대시보드 | 오늘 방문자·페이지뷰·구매 버튼 클릭·지금 보는 사람, 최근 14일 흐름, 할 일(새 오류 신고, 새 문의, 커뮤니티 신고, 쿠팡 실적 입력, 검수 중 원고), 설정 상태 |

| 지표 › 검색·참여 | 사이트 안 검색어와 결과가 없던 검색어(새 원고 후보), 기능 사용, 커뮤니티 활동 |
| 지표 › 실시간 | 최근 5분·30분 방문자, 지금 열린 페이지, 최근 구매 버튼 |
| 원고 관리 · 오류 신고 · 문의함 · 커뮤니티 | 예전과 같아요 |

| 쿠팡 실적 입력 | 쿠팡 파트너스 리포트의 날짜별 클릭·구매 건수·합산 금액·수익을 옮겨 적어요. 표를 복사해 한꺼번에 붙여 넣을 수도 있어요 |
| 설정·도움말 | 이 기기 통계 빼기, Cloudflare 설정 상태, 모은 기록 수, 지표 설명 |

지표 화면은 위쪽에서 기간(오늘·어제·7일·30일·90일·직접)을 고르고, 표 머리를 누르면 정렬되고, ‘CSV 내려받기’로 엑셀에서 열 수 있어요.

#### 방문 통계는 이렇게 모아요

- 페이지를 열면 `/api/event`로 페이지 기록을 보내고, 떠날 때 화면을 보고 있던 시간과 스크롤 정도를 보내요(`src/static/js/app.js`의 ‘방문 통계’).
- 방문자는 브라우저에 저장한 무작위 번호(`rs-vid`), 방문은 30분 동안 아무것도 안 하면 새로 세는 번호(`rs-ses`)로 구분해요. 이름·IP·로그인 정보와 잇지 않아요.
- 구매 버튼(`/go/`)은 누를 때 방문 번호와 페이지를 붙여 보내서, 어느 방문·어느 게임에서 눌렀는지 세요. 검색 로봇과 미리보기 봇은 빼요.
- 쿠팡 주문·구매액·수익은 쿠팡이 알려 주지 않아서 ‘쿠팡 실적 입력’에 옮겨 적은 숫자를 써요. 쿠팡은 링크로 들어온 뒤 24시간 안의 모든 구매를 실적으로 잡아요.
- 원본 기록은 400일이 지나면 지워요. 개인정보처리방침에 ‘방문 통계’ 항목과 ‘방문 통계 끄기’ 버튼이 있어요.
- 코드: `server/kpi.js`(모으기·지표), `server/adminauth.js`(로그인), `src/static/js/admin.js`(화면).

## 2. 원고 고치기 (GitHub 웹에서)

게임 설명은 `content/games` 폴더에 게임마다 JSON 파일 하나로 들어 있어요. 파일을 열고 연필 모양(Edit)을 눌러 고친 뒤 **Commit changes**를 누르면 Cloudflare가 1~2분 안에 사이트를 다시 만들어요.

### 원고 항목

| 항목 | 뜻 |
| --- | --- |
| `slug` | 주소에 쓰는 영문 이름. 파일 이름과 같아야 해요 (`halli-galli.json` → `halli-galli`) |
| `code` | 매장 QR 주소에 쓰는 영문 소문자, 숫자 2~3자. 다른 게임과 겹치면 안 돼요 |
| `name`, `original`, `aliases` | 한국어 이름, 원래 이름, 검색에 쓸 다른 이름 |
| `kind` | `board`(보드게임) 또는 `traditional`(전통놀이) |
| `group` | `family`, `party`, `strategy`, `traditional` 가운데 하나 |
| `players`, `minutes` | `[최소, 최대]`. 인원에 99를 쓰면 ‘n명 이상’으로 보여요 |
| `age`, `level` | 나이, 난이도(1 쉬움, 2 보통, 3 어려움) |
| `tags` | 분위기 거르기에 쓰는 말 |
| `oneLine`, `intro`, `compare` | 한 줄 소개, 소개 문단, 비슷한 게임과 비교 |
| `summary` | 1분 요약: `goal`(이기는 법), `turn`(내 차례, 목록), `end`(끝나는 때) |
| `components`, `setup` | 구성물, 준비하기 |
| `examples`, `scoring` | 따라 해 보기 예시, 끝내기와 점수 |
| `rules` | 자세한 규칙: `{ "title": "...", "items": ["...", "..."] }` 목록 |
| `tricky`, `faq` | 헷갈리는 상황, 자주 묻는 질문: `{ "q": "...", "a": "..." }` 목록 |
| `variants` | 인원별 규칙이나 다른 방법 |
| `houseRules` | 우리 집 규칙 정하기에 나오는 하우스룰: `{ "id": "영문", "title": "...", "text": "..." }` |
| `tools` | 테이블 모드에 먼저 보일 도구: `score`, `timer`, `dice`, `first`, `team`, `yut`, `roles` |
| `related` | 비슷한 게임의 `slug` 목록 |
| `diagram` | 그림: `yut-board`, `umul-gonu`, `chilgyo` 가운데 하나 (없으면 빈칸) |
| `status`, `checked` | 검수 상태. 아래를 보세요 |

- 문장 안에서 `**두 별표**`로 감싼 부분은 굵게 보여요.
- JSON은 쉼표와 따옴표에 민감해요. 고친 뒤 배포가 실패하면 Cloudflare의 배포 기록을 열어 보세요. 어느 파일의 어느 항목이 문제인지 한국어로 적혀 있어요.

### 검수 완료로 바꾸기

실제로 게임을 해 보며 확인했다면 두 줄을 이렇게 바꿔요.

```json
"status": "checked",
"checked": { "date": "2026-12-01", "by": "확인한 사람" },
```

게임 페이지의 ‘검수 중’ 안내가 ‘검수 완료 (날짜, 확인한 사람)’로 바뀌어요.

### 새 게임 넣기

운영 관리 화면의 **원고 관리 → 새 게임 원고 만들기**를 누르면 빈 원고가 채워진 GitHub 새 파일 화면이 열려요. 파일 이름과 `slug`를 같은 영문 이름으로 바꾸고, `code`를 겹치지 않게 정한 뒤 저장해요. 비슷한 게임 파일을 복사해서 고쳐도 돼요.

### 그 밖의 원고

- `content/stories/게임.json`: 게임 이야기. `title`(제목), `teaser`(‘알고 계셨나요?’에 나오는 한 줄), `facts`(처음 나온 해, 만든 사람 같은 표), `lead`, `sections`, `trivia`, `quiz`(문제, 보기 `o`, 정답 번호 `a`는 0부터, 풀이 `why`)로 이루어져요. 확실하지 않은 이야기는 ‘~라고 전해져요’처럼 적어 주세요.
- `content/test.json`: 취향 테스트의 질문과 8가지 유형 설명, 게임마다 맞는 유형(`games`, 앞이 주 유형)
- `content/collections.json`: 처음 화면의 ‘요즘 많이 여는 게임’(`popular`)과 ‘이런 자리라면’ 묶음
- `content/glossary.json`: ‘처음이라면’ 페이지의 용어 풀이
- `content/venues.json` (선택): 매장 전용 고정 페이지. 만들면 `/space/매장영문이름/` 주소가 생겨요. `view`는 쓸 수 없어요.

  ```json
  [
  ```

## 3. 사이트 설정 (`site.config.json`)

| 항목 | 뜻 |
| --- | --- |
| `siteName`, `tagline` | 서비스 이름(룰룰)과 이름 옆에 붙는 설명 문구(보드게임 룰 하는법 설명서) |
| `siteTitle`, `description` | 첫 화면 제목, 검색 설명 |
| `siteUrl` | 실제 사이트 주소. 도메인을 연결하면 바꿔 주세요 |
| `githubRepo`, `githubBranch` | 운영 관리 화면의 ‘고치기’ 링크에 쓰여요 |
| `contactEmail` | 소개 페이지에 보일 문의 메일 (비워 두면 안 보여요) |
| `naverSiteVerification`, `googleSiteVerification` | 네이버 서치어드바이저, 구글 서치 콘솔 소유 확인 값 |

도메인을 연결하려면 Pages 프로젝트의 **Custom domains**(사용자 지정 도메인)에서 추가하고 `siteUrl`을 바꿔요. 검색 등록은 사이트맵 주소 `https://(주소)/sitemap.xml`을 네이버와 구글에 제출하면 돼요.

### 검색 노출 (네이버, 구글)

- 게임마다 `content/seo.json`에 제목 끝에 붙는 핵심 주제(`hooks`)와 많이 찾는 검색어(`kw`)가 있어요. 제목은 ‘루미큐브 하는법·룰 총정리 | 조커·등록 30점·점수 계산’처럼 만들어져요.
- 사이트맵 `https://rulerule.kr/sitemap.xml`과 RSS `https://rulerule.kr/rss.xml`을 네이버 서치어드바이저(요청 → 사이트맵 제출, RSS 제출)와 구글 서치 콘솔(Sitemaps)에 제출해 주세요.
- 네이버 소유 확인 파일(`/naver166f723b5ee950517c79af0092638755.html`)은 `functions/`의 함수가 바로 답해요. Cloudflare Pages가 `.html` 주소를 다른 주소로 옮기는 것을 피하려는 거예요.
- 게임별 공유 이미지(1200×630)는 `src/static/img/og/`에 있어요.
- `www.rulerule.kr`과 `rulerule.pages.dev`는 표준 주소(canonical)가 `rulerule.kr`을 가리켜요. 주소창까지 옮기고 싶다면 Cloudflare 대시보드 → rulerule.kr → Rules → Redirect Rules에서 `www.rulerule.kr/*` → `https://rulerule.kr/$1`(301)을 만들어 주세요.

## 4. 보드게임몰과 쿠팡 파트너스

- 상품 목록은 `content/shop.json`이에요. `items`(상품 이름, 쿠팡 검색어, 한 줄 설명), `games`(게임 페이지에 보일 상품, 첫 번째가 본판), `shelves`(보드게임몰 진열대)로 되어 있어요.
- 상품마다 쿠팡에서 후기가 가장 많은 알맞은 상품을 골라 `cp`(상품 번호), `img`(상품 사진 경로), `cpName`(쿠팡 상품 이름), `reviews`(고를 때의 후기 수)를 넣어 두었어요. 사진은 쿠팡 이미지 서버의 사진을 크기만 바꿔 보여 줘요.
- 구매 버튼은 `/go/상품id`로 가요. 서버는 ① 운영 관리에 저장한 파트너스 링크 ② 원고의 `url`(파트너스 링크) ③ 고른 쿠팡 상품 페이지 ④ 쿠팡 검색 결과 순서로 보내요. ③과 ④에는 수수료가 생기지 않아요.
- 2026년 11월 18일 기준으로 78개 상품 모두 원고의 `url`에 파트너스 단축 링크(`https://link.coupang.com/a/...`)를 넣어 두었어요. 쿠팡 파트너스 → 링크 생성 → 간편 링크 만들기에서 `cp`의 상품 페이지 주소로 만든 링크예요.
- 쿠팡이 파트너스 상품 링크를 막아 둔 상품(‘smart-filter blacklist’)은 링크가 만들어지지 않아요. 부루마불은 다른 판(부루마불 프렌즈)으로 바꿨고, 바퀴벌레 포커는 파트너스용 상품이 없어 쿠팡 검색 결과로 가는 파트너스 링크를 넣었어요(`cpNote`).
- `coupang-boardgames`는 보드게임몰 아래쪽 ‘쿠팡에서 보드게임 더 보기’ 버튼이에요. 쿠팡 보드게임 검색 결과로 가는 파트너스 링크예요.
- 상품을 바꾸면 `cp`와 `img`를 고치고, 간편 링크 만들기에서 새 링크를 만들어 `url`도 함께 바꿔 주세요. `url`이 예전 상품을 가리키면 버튼이 예전 상품으로 가요.
- 파트너스 링크는 운영 관리 → **쇼핑 링크**에서 붙여 넣으면 바로 쓰여요. 클릭 수가 많은 상품이 위에 보여요.
- 쿠팡 파트너스 Open API 승인을 받았다면 Cloudflare 비밀 값에 `COUPANG_ACCESS_KEY`, `COUPANG_SECRET_KEY`를 넣고 ‘빈 링크 자동 만들기’를 누르면 돼요.
- 대가성 문구는 구매 상자와 보드게임몰 맨 위, 바닥글에 들어가 있어요. 지우지 마세요.

## 5. 커뮤니티와 문의

- 회원가입은 아이디, 닉네임, 비밀번호만 받아요. 만 14세 이상 확인과 약관, 개인정보 동의를 받아요. 비밀번호는 PBKDF2로 바꿔 저장해요.
- 비밀번호를 잊은 회원은 제휴·문의로 연락하고, 운영 관리 → 커뮤니티 → ‘임시 비밀번호’로 새 비밀번호를 만들어 알려 주면 돼요.
- 서로 다른 회원 다섯 명이 신고한 글은 자동으로 가려지고, 운영 관리 → 커뮤니티에서 ‘다시 보이기’, ‘지우기’, ‘이용 제한’을 할 수 있어요.
- 제휴·문의는 운영 관리 → **문의함**에 쌓여요. `INQUIRY_WEBHOOK_URL`(슬랙이나 디스코드 웹훅 주소)을 넣으면 새 문의가 왔다는 알림만 보내요(개인 정보는 보내지 않아요).
- `site.config.json`의 `operatorName`, `privacyOfficer`, `privacyEmail`을 채우면 이용약관과 개인정보처리방침에 운영자와 개인정보 보호책임자가 표시돼요.

### 등급, 점수, 배지

- 점수 규칙과 등급, 배지 목록은 `server/growth-data.js` 한 파일에 모여 있어요. 숫자를 바꾸고 다시 배포하면 서버와 화면, 등급 안내 페이지에 함께 반영돼요.
- 같은 글이나 후기로 점수를 두 번 받을 수 없고, 활동마다 하루 한도가 있어요. 글, 댓글, 후기를 지우면 받았던 점수도 빠져요.
- 받은 별은 좋아요, 후기 ‘도움돼요’, 답변 채택(별 3개)으로 쌓여요. 매너 별점은 정모·번개가 끝나고 14일 안에 함께한 사람끼리 남기고, 3명 넘게 평가해야 프로필에 보여요.
- 취향 테스트(+10, 하루 한 번), 보드게임 월드컵(+3, 하루 한 번), 퀴즈를 다 맞혔을 때(+3, 이야기마다 한 번·하루 5번)에도 점수를 받아요. 결과는 회원이 아니어도 `fun_stats` 표에 숫자로만 모이고, 운영 관리 → 지표 KPI의 ‘기능 사용’에서 테스트·월드컵·퀴즈를 끝까지 한 횟수를 볼 수 있어요.
- 처음 배포하면 ‘룰룰 운영팀’ 이름으로 커뮤니티 안내 공지와 투표 하나가 자동으로 올라가요. 운영 관리 → 커뮤니티에서 공지와 투표를 더 올리고, 맨 위 고정을 켜고 끌 수 있어요. 게임 후기도 같은 곳에서 가리거나 지울 수 있어요.

| Cloudflare 비밀 값 | 필요 여부 | 뜻 |
| --- | --- | --- |
| `ADMIN_PASSWORD` | 필수 | 운영 관리 화면 비밀번호 |
| `COUPANG_ACCESS_KEY`, `COUPANG_SECRET_KEY` | 선택 | 쿠팡 파트너스 링크 자동 만들기 |
| `INQUIRY_WEBHOOK_URL` | 선택 | 새 문의 알림 |
| `AUTH_PEPPER` | 선택 | 비밀번호 저장에 더하는 비밀 값. 한 번 정하면 바꾸지 마세요 |
| `PBKDF2_ITER` | 선택 | 비밀번호 반복 횟수(기본 20000). 유료 요금제라면 100000까지 올려도 돼요 |

## 6. 폴더 구조

```
content/            원고 (게임 JSON, 게임 이야기, 취향 테스트, 묶음, 용어)
scripts/build.mjs   원고를 읽어 public/에 페이지를 만드는 스크립트 (Node 18 이상, 설치할 것 없음)
scripts/fun.mjs     이야기, 취향 테스트, 월드컵, 퀴즈 페이지를 만드는 부분
src/static/         화면 스타일(css), 스크립트(js), 이미지(img), 서비스 워커, 헤더 설정
functions/          서버 기능의 주소 (api, go, 네이버 확인 파일)
server/             서버 기능의 내용: 회원, 커뮤니티, 후기·성장(social, growth), 재미 기능 결과(fun), 문의, 보드게임몰, 운영 관리
public/             빌드 결과물 (저장소에는 올리지 않고, Cloudflare가 배포할 때 만들어요)
```

컴퓨터에서 직접 빌드해 보려면 `npm run build`를 실행하면 돼요. 따로 설치할 패키지는 없어요.

## 7. 개인 정보와 저작권

- 이용 기록은 날짜, 종류, 게임, 매장 이름별 숫자만 세요. 방문자를 알아볼 수 있는 값은 저장하지 않아요.
- 틀린 곳 알려 주기는 방문자가 직접 적은 내용과 선택으로 남긴 연락처만 저장해요. 같은 사람이 짧은 시간에 너무 많이 보내지 못하게, 접속 주소를 그날만 쓰는 값으로 바꿔(해시) 함께 저장해요.
- 회원 정보와 커뮤니티 글, 문의 내용은 Cloudflare D1에 저장돼요. 보관 기간과 지우는 방법은 사이트의 개인정보처리방침(/privacy/)에 적어 두었어요.
- 게임 설명은 규칙을 우리 말로 다시 쓴 것이에요. 룰북 문장, 그림, 상자 이미지는 쓰지 않아요. 게임 이름과 상표는 각 권리자의 것이에요.
- QR 코드 생성에는 Kazuhiko Arase의 qrcode-generator(MIT 라이선스)를 썼어요. 글꼴은 Pretendard와 Black Han Sans(SIL Open Font License)를 CDN으로 불러와요.
